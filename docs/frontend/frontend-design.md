# NoteLy frontend

Статичний frontend на HTML, CSS і ES modules: без збірки, фреймворків і runtime-залежностей. Усі мережеві запити проходять через спільний API-клієнт та узгоджені з бекендом. Для відкладених можливостей (наприклад, історії версій і форматування) є лише вимкнені візуальні елементи.

## Запуск локально

У корені репозиторію, у першому терміналі запустіть бекенд:

```sh
.venv/bin/uvicorn src.api.main:app --reload --host 127.0.0.1 --port 8000
```

Для цього прикладу у `.env` бекенду має бути дозволений origin:

```env
CORS_ALLOWED_ORIGINS=http://localhost:3000
```

У другому терміналі запустіть статичний сервер:

```sh
python3 -m http.server 3000 --directory frontend
```

Відкрийте <http://localhost:3000/login.html>. Для окремих екранів доступні `register.html`, `workspace.html`, `trash.html` та `document.html?id=<id>`; захищені сторінки самі перенаправляють на вхід, якщо сесії немає.

Якщо порт зайнятий, не завершуйте невідомий процес. Перевірте, чи це вже потрібний сервер, або використайте інший порт, наприклад `3001`, і дозвольте саме `http://localhost:3001` у `CORS_ALLOWED_ORIGINS`. Після зміни `.env` перезапустіть бекенд. Не використовуйте `*` для CORS. Frontend і API мають бути на різних портах.

## Розгорнута версія

Frontend доступний як окремий Render Static Site: <https://noproblem-wtf5.onrender.com>. API працює на окремому Render Web Service: <https://notely-xf7b.onrender.com/api-docs>. Запити з frontend дозволені в API через `CORS_ALLOWED_ORIGINS`.

## Налаштування та запити

- API base URL заданий у `js/core/config.js` (`API_BASE_URL`): локально `http://localhost:8000/api/v1`; frontend на Render звертається до `https://notely-xf7b.onrender.com/api/v1`.
- CSP `connect-src` у HTML-сторінках дозволяє локальний і production API. Якщо адреса production API зміниться, оновіть `config.js` та CSP синхронно.
- Статичний сервер не має власних змінних середовища. Адреса API не дублюється в модулях сторінок.
- Точний контракт ендпоінтів, тіл, відповідей, помилок і функціональних обмежень: [`../docs/frontend/api-contract.md`](../docs/frontend/api-contract.md).

## Як влаштований frontend

### Сторінки

- `login.html`, `register.html` — вхід і створення акаунта.
- `unlock/index.html` — розблокування акаунта за наданим бекендом токеном.
- `workspace.html` — активні документи, пошук, створення, перейменування та переміщення в кошик.
- `trash.html` — кошик і доступне власнику відновлення документа.
- `document.html?id=<id>` — перегляд/редагування назви та абзаців, коли роль можна підтвердити.

Кожна HTML-сторінка підключає лише власний ES-модуль. Inline-скриптів і inline-стилів немає.

### CSS і ресурси

- `css/tokens.css` — кольори, типографіка, радіуси, відступи та інші спільні CSS variables.
- `css/base.css` — reset, базова типографіка, фокус і утиліти доступності.
- `css/components.css` — спільні кнопки, форми, діалоги, повідомлення, toast та стани завантаження.
- `css/pages/` — невеликі додатки стилів для workspace та редактора.
- `assets/` — локальні SVG-іконки й графіка; браузер не завантажує ассети з тимчасових посилань Figma.

### JavaScript-шари й потік даних

- `js/core/config.js` зберігає конфігурацію API.
- `js/core/session.js` керує токеном у `sessionStorage`; `js/core/guard.js` перевіряє сесію перед показом захищених сторінок і спрямовує вже автентифікованого користувача з форми входу до робочого простору.
- `js/api/client.js` — єдина точка `fetch`: додає Bearer-токен, обмежує час запиту через `AbortController`, перетворює серверні, timeout та мережеві помилки на `ApiError`, обробляє `401` і підтримує `Idempotency-Key`.
- `js/api/auth.js`, `js/api/documents.js` — типізовані за призначенням обгортки над фактичними маршрутами бекенду; вони не містять UI.
- `js/pages/` обробляє події сторінки, показує стани та викликає API-модулі. Дані користувача вставляються через `textContent`, DOM-методи та властивості полів.
- `js/core/app-shell.js`, `document-list.js`, `document-save-queue.js` — повторно використовуваний shell, список документів та черга автозбереження.

Потік типового запиту: сторінка → доменний API-модуль → спільний `client.js` → FastAPI; результат повертається в сторінку для точкового оновлення DOM.

### Автентифікація та помилки

Після входу токен зберігається лише в `sessionStorage`, не в URL чи логах. Вихід очищає локальну сесію. `401` очищає її та переводить користувача на сторінку входу; `403`, помилки полів, недоступний сервіс, timeout і відсутність мережі показуються зрозумілими повідомленнями без сирих stack trace чи внутрішніх деталей.

### Робочий простір і кошик

Список читається з API сторінками; пошук починається від двох символів і використовує той самий API-контракт. Створення документа генерує новий `crypto.randomUUID()` для кожної дії та вимикає кнопку на час запиту. Назви й результати пошуку додаються до DOM без `innerHTML`. Перейменування проходить клієнтську перевірку 1–100 символів; сервер лишається джерелом істини. Кошик дозволяє відновлення лише користувачеві з підтвердженою роллю Owner.

### Документ і автозбереження

Сторінка паралельно завантажує документ, абзаци та доступні їй ролі. Назва має 1–100 символів, текст кожного абзацу — максимум 10 000 символів. `document-save-queue.js` буферизує введення 800 мс, послідовно зберігає кожне поле, показує «Зберігаємо…» / «Збережено» / помилку, автоматично повторює мережеву помилку через 5 секунд і попереджає про закриття/перехід, доки є незбережені дані. Перед структурною зміною черга має зберегти зміни; видалення абзацу потребує підтвердження.

API повертає абзаци як звичайні текстові рядки й не має схеми форматування. Тому панель форматування показана, але вимкнена; frontend не вигадує формат тексту та не кодує його в `content`. `GET /documents/{id}/access` дозволяє перегляд ролей лише Owner. Для Editor і Guest API повертає однаковий `403`, а документ не містить ролі поточного користувача. За обраним безпечним правилом обидва невизначені випадки відображаються лише для читання; наслідок — реальні Editor-користувачі теж не можуть редагувати через поточний frontend.
