# ADR-002: Вибір бази даних

- **Статус:** Прийнято
- **Дата:** 2026-09-30

## Контекст

Система повинна зберігати:

- користувачів;
- ролі та права доступу;
- документи та їхній вміст;
- версії документів;
- запити на доступ;
- події календаря та їхніх учасників.

Більшість цих даних має чіткі реляційні зв'язки. Зокрема, система повинна підтримувати зв'язки між власниками документів, редакторами та гостями, а також зберігати історію версій.

## Варіанти

1. **Реляційна база даних — PostgreSQL.**
2. **Документоорієнтована база даних — MongoDB.**
3. **Гібридний підхід** — PostgreSQL для метаданих і доступу та окреме сховище для вмісту документів.

## Рішення

Обрати **PostgreSQL** як основну базу даних.

Використовувати реляційну схему з окремою таблицею `Paragraph` для зберігання вмісту документів.

## Обґрунтування

Зв'язки `Owner–Document–Editor/Guest`, ролі та дозволи, а також версії документів із timestamp та автором добре відповідають реляційній моделі PostgreSQL.

Foreign keys дозволяють забезпечити цілісність зв'язків між сутностями.

Транзакції PostgreSQL важливі для FR-013, оскільки вони дозволяють уникати появи неповних або "битих" записів у разі розриву з'єднання під час операції.

Окрема таблиця `Paragraph` також є прямим наслідком рішення з ADR-001. Вона дозволяє оновлювати та блокувати один абзац без необхідності перезаписувати весь документ.

## Наслідки

- PostgreSQL стає єдиним основним джерелом даних системи.
- Вміст документа зберігається окремими записами в таблиці `Paragraph`.
- Один абзац можна оновлювати незалежно від інших абзаців документа.
- Якщо в майбутньому буде обрано гібридну архітектуру або іншу СУБД, необхідно буде документувати два джерела істини в `data-model.md`.
- Повнотекстовий пошук відповідно до FR-058–062 може бути реалізований за допомогою вбудованого механізму `tsvector` PostgreSQL для поля `content` таблиці `Paragraph`.
