# ADR-001: Стратегія розв'язання конфліктів одночасного редагування

- **Статус:** Прийнято
- **Дата:** 2026-09-30

## Контекст

FR-024 явно вимагає відсутність конфліктів при одночасному редагуванні одного фрагмента тексту кількома користувачами.

Необхідно обрати механізм, який гарантуватиме узгодженість даних під час спільного редагування документа.

## Варіанти

1. Використання Node.js та CRDT-підходу для підтримки паралельного редагування.
2. Блокування абзацу на час його редагування.

## Рішення

Обрати **блокування абзацу**.

Коли один користувач редагує абзац, він отримує блокування цього абзацу. Інші користувачі не можуть редагувати його до моменту зняття блокування.

## Обґрунтування

Команда обмежена часом семестру та не має достатнього досвіду роботи зі стеком Node.js і CRDT-бібліотеками, щоб гарантовано інтегрувати таке рішення коректно.

Блокування абзацу значно простіше реалізувати, протестувати та пояснити під час демонстрації проєкту. Воно також гарантовано виключає конфлікт запису на рівні даних.

Це свідомо прийнятий компроміс: технічно рішення дещо відхиляється від букви FR-024, оскільки другий редактор повинен зачекати, а не редагувати той самий абзац паралельно. Водночас зберігається основна мета вимоги: дані не втрачаються, а всі користувачі бачать актуальний стан документа.

## Наслідки

- Необхідно реалізувати автоматичне зняття блокування при розриві з'єднання з редактором.
- Таймаут блокування має бути узгоджений із FR-026, відповідно до якого курсор користувача вважається зниклим через 5 секунд.
- Блокуванням абзаців керує `Lock Manager`, який є частиною компонента `Collab` (спільне редагування) на компонентній діаграмі.
- Блокування зберігаються лише в пам'яті серверного процесу `Collab` і не записуються в базу даних. Після перезапуску сервера всі блокування скидаються.
- Блокування створюють лише користувачі з ролями Owner та Editor; Guest блокувань не створює.
- Вміст документа зберігається окремо по абзацах, а не одним blob.
- Це рішення безпосередньо впливає на структуру бази даних та є підставою для рішення, описаного в ADR-002.
