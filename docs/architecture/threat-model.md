# STRIDE-модель загроз NoteLy
## 1. Межі довіри
**На діаграмі розгортання визначено такі межі довіри:**
* TB1 — недовірена зона: пристрій користувача / веб-браузер ↔ сервер NoteLy.
* TB2 — довірена зона: серверне середовище NoteLy.
* TB3 — зона даних: сервер NoteLy ↔ сервер бази даних.
* TB4 — зовнішня зона: NoteLy ↔ зовнішній Email Service.

Основні точки аналізу: Web → GW, Docs/IAM/Search/Calendar → DB та IAM → Mail.
## 2. STRIDE-аналіз

| ID | Компонент / межа       | STRIDE                         | Сценарій                                                                                                                          | Рівень  | Контрзахід                                                                                                               |
| -- | ---------------------- | ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------ |
| R1 | TB1: Web ↔ GW / IAM    | **S — Spoofing**               | Зловмисник отримує або підробляє токен/сесію та надсилає запити від імені іншого користувача.                                     | Висока  | Перевіряти токен на сервері через IAM, використовувати HTTPS/WSS та контроль терміну дії сесії.                          |
| R2 | IAM / Docs             | **E — Elevation of Privilege** | Користувач із роллю `GUEST` або `EDITOR` змінює запит так, щоб отримати права `EDITOR` або `OWNER` для документа.                 | Висока  | Перевіряти роль користувача на сервері перед кожною операцією та використовувати IAM як єдине джерело правди про доступ. |
| R3 | Search ↔ DB            | **I — Information Disclosure** | Через помилку ACL-фільтра пошук повертає користувачу назву або вміст чужого документа.                                            | Висока  | Перевіряти права доступу через IAM перед поверненням результатів пошуку та фільтрувати результати за користувачем.       |
| R4 | Docs ↔ DB              | **T — Tampering**              | Несанкціонований запит змінює `Document.content` або `DocumentVersion.content_snapshot` у сховищі.                                | Висока  | Серверна авторизація операцій, обмеження доступу до DB та перевірка прав на документ перед зміною.                       |
| R5 | Docs / DocumentVersion | **R — Repudiation**            | Користувач заперечує виконання зміни документа, якщо неможливо встановити автора та час зміни.                                    | Середня | Зберігати автора та час створення кожної версії документа і використовувати історію версій для фіксації змін.            |
| R6 | GW / Collab            | **D — Denial of Service**      | Зловмисник створює велику кількість HTTP-запитів або WebSocket-з'єднань і перевантажує сервер NoteLy.                             | Середня | Використовувати rate limiting на Gateway, обмеження WebSocket-з'єднань та розміру запитів.                               |
| R7 | IAM ↔ Mail             | **I — Information Disclosure** | Через помилку в адресі одержувача або формуванні листа дані запрошення чи розблокування можуть бути надіслані іншому користувачу. | Середня | Перевіряти адресу одержувача, не передавати зайві дані в листі та використовувати TLS для SMTP/API.                      |
| R8 | Calendar / IAM         | **E — Elevation of Privilege** | Користувач отримує доступ до події або учасників календаря, не маючи відповідного доступу до документа чи події.                  | Середня | Перевіряти права через IAM перед читанням і зміною подій та списку учасників.                                            |

## 3. Використані категорії STRIDE
* S — Spoofing: підміна користувача або сесії.
* T — Tampering: несанкціонована зміна документа або версії.
* R — Repudiation: заперечення виконаної зміни.
* I — Information Disclosure: витік документів або даних користувачів.
* D — Denial of Service: перевантаження Gateway або WebSocket.
* E — Elevation of Privilege: отримання ролі або доступу, яких користувач не повинен мати.
