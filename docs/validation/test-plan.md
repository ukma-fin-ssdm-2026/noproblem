# План тестування NoteLy (чернетка)

**Обсяг:** API автентифікації, створення документів та контролю доступу, включно з перевірками прав і повторних запитів. Не тестуємо клієнтський інтерфейс, WebSocket-співредагування, пошук і реальну поштову/production-інфраструктуру.

**Критерії виходу:** усі наведені кейси успішні в CI; покриття рядків і гілок `src` не нижче 90% згідно зі стратегією тестування; немає відкритих критичних дефектів.

**Ризики:** найвища ціна помилки — несанкціонований доступ до документів; далі — дублікати чи некоректний стан документа при повторі/перериванні запиту; також блокування входу або повільна автентифікація. Таблицю впорядковано за цими ризиками.

| № | Компонент/функція | Рівень тесту | Тип | Очікуваний результат / критерій прийняття | Власник | Вимога |
|---:|---|---|---|---|---|---|
