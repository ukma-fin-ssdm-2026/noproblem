# План тестування NoteLy (чернетка)

**Обсяг:** API автентифікації (реєстрація, вхід, блокування після невдалих спроб), створення документів та контролю доступу, включно з перевірками прав і повторних запитів. Не тестуємо клієнтський інтерфейс, WebSocket-співредагування, пошук, зміну режиму доступу «Обмежений»/«За посиланням» (FR-045 — ще не реалізовано в API, кейси Test-22 буде додано разом із реалізацією) і реальну поштову/production-інфраструктуру (розблокування за посиланням з email перевіряємо лише на рівні API з тестовим токеном).

**Критерії виходу:** усі функціональні кейси плану успішні в CI; покриття рядків і гілок `src` не нижче 90% згідно зі стратегією тестування; кейс продуктивності (№ 11) пройдено окремим прогоном у контрольованому середовищі, результат додано до звіту тестування; немає відкритих критичних дефектів (критичний — дефект, що порушує NFR-SEC-* або призводить до втрати чи дублювання даних).

**Ризики:** найвища ціна помилки — несанкціонований доступ до документів; далі — дублікати чи некоректний стан документа при повторі/перериванні запиту; також блокування входу або повільна автентифікація. Таблицю впорядковано за цими ризиками.
