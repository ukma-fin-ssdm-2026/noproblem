# Звіт з перевірки якості коду — YourPathUkma API

**Об'єкт перевірки:** `src/api/common.py`, `src/api/main.py`, `src/api/routes/disciplines.py`, `src/api/routes/plans.py`, а також `AGENTS.md` і документація проєкту (як джерело вимог).
**Метод:** ручний рев'ю коду з порівнянням із вимогами `AGENTS.md`. Лінтери й тести **не запускалися**; зауваження щодо стилю — це те, що, імовірно, виявлять `ruff`/`flake8`, і їх треба підтвердити запуском (команди в розділі 5).

## 1. Стиль і стандарти кодування

**Що добре**
- Послідовне іменування: `snake_case` для функцій і змінних, `PascalCase` для класів, `UPPER_CASE` для констант, `_` для приватних об'єктів (`_CATALOG`, `_find_plan`).
- Анотації типів майже скрізь; використано `Optional`, `List`, `Enum`.
- Коментарі й описи українською, ідентифікатори англійською — послідовно.

**Що виправити**
- Порожні рядки між визначеннями верхнього рівня (PEP 8: два). Приклади: перед `class ErrorDetail`, `class PaginationInfo`, `MOCK_STUDENT_ID` у `common.py`; перед `class Discipline`, `_CATALOG`, `@router.get` у `disciplines.py`; перед `class PlanStatus`, `_SAMPLE_PAYLOAD`, `@router.post` у `plans.py`.
- Зайві пробіли в кінці рядка: `FREE_ELECTIVE_LIMIT = 25  ` (`plans.py`), `save_openapi_spec(app) `, `docs_url="/api-docs",  ` (`main.py`).
- `from fastapi.middleware.cors import CORSMiddleware` стоїть посеред `main.py`, після `lifespan` (E402). Усі імпорти мають бути нагорі.
- Порожній рядок одразу після `def health_check():` без docstring.
- Порядок імпортів не відсортований (`isort`/`ruff`).
- Назви змішують терміни: `course` (рік навчання) і `course_id` (ID дисципліни) в одній моделі `PlanItem`/`CreatePlanRequest`; у `Discipline` те саме поле називається `id`. Краще: `study_year` і `discipline_id`.
- `LoadLevel` і `LoadLevels` легко сплутати; зрозуміліше `TrimesterLoad`.

## 2. Якість і підтримуваність

**Що добре**
- Файли невеликі й зрозумілі, один ресурс — один модуль.
- Допоміжні функції (`_build_response`, `_find_plan`, `error_responses`) прибирають частину повторів.

**Що виправити**
- **Дублювання рядків і правил.** Повідомлення про відсутній токен записане двічі в `get_current_student_id`; тексти помилок живуть і в `_DEFAULT_EXAMPLES`, і в місцях `raise ApiError(...)`; константи `_PLAN_NOT_FOUND` дублюють рядки з `_find_plan`.
- **Повторювані параметри.** `limit`/`offset` (`Query`) описано окремо в двох ендпоінтах, `plan_id` (`Path(..., gt=0, ...)`) — чотири рази. Формула `has_more` теж повторюється.
- **Неоднакові підходи.** Авторизація через `dependencies=[...]` на рівні роутера в `disciplines.py` і через `Depends` у кожному ендпоінті в `plans.py`; перевірки `if trimester:` поруч із `is not None`.
- **Неточні приклади в OpenAPI.** `error_responses` для кожного коду 422 показує `items.0.credits`, навіть для `GET /disciplines`, де такого поля немає.
- **`common.py` — «шухляда»:** помилки, пагінація й автентифікація в одному файлі.
- Магічні числа `1/2/3` для триместрів повторюються в кількох місцях; краще `Trimester` enum.
- Для кредитів використано `float`; суми й порівняння з 25 краще робити через `Decimal` або кредити в півкредитах.

## 3. Безпека

**Що добре**
- Декларативна валідація вводу: `ge/le/gt`, `min_length/max_length`, `max_length=30` для `items`, обмеження `limit ≤ 100`, enum-и для статусів і типів.
- Обробник `RequestValidationError` повертає лише `loc` і `msg`, без значень, які надіслав клієнт; обробник `Exception` не розкриває внутрішніх подробиць.
- Перевірка власника плану (`_find_plan`) і заборона зміни/видалення не-чернеток (409).

**Що виправити**
- **Журналювання відсутнє.** Використано лише `print`. Немає логів для 401/403, помилок валідації, необроблених винятків (у `unhandled_error_handler` немає `logger.exception`) і немає ідентифікатора запиту (request ID).
- **Керування сесіями/токенами.** Токен не перевіряється зовсім: підпис, `exp`, `aud`, домен пошти (`ukma.edu.ua`) не перевіряються; будь-який непорожній рядок дає `student_id = 42`. Для заглушки це нормально, але потрібен чіткий TODO і тест, що заглушка не потрапить у продакшн.
- **Довіра до даних клієнта.** `title`, `credits` і `is_free_elective` приходять від клієнта, а `course_id` не звіряється з каталогом. Клієнт може позначити всі дисципліни як `is_free_elective=false`, щоб обійти ліміт 25 кредитів, або вказати довільні кредити.
- **Ліміт 25 кредитів перевіряється лише в межах одного плану**, тоді як `AGENTS.md` вимагає ліміт сумарно за 4 роки. Не перевіряються також 240 кредитів, 57–60 кредитів на рік і конфлікти з нормативними дисциплінами.
- **Перелік існування ресурсів (IDOR-розвідка).** Чужий план дає 403, неіснуючий — 404, тож сторонній може перебирати послідовні ID і дізнаватися, які плани існують. Безпечніше повертати 404 в обох випадках.
- `allow_origins=["*"]` — для продакшну треба обмежити origin фронтенду.
- `uvicorn.run(host="0.0.0.0", reload=True)` і публічні `/api-docs`, `/redoc` — прийнятно для розробки, але не для продакшну.
- Немає обмеження частоти запитів (rate limiting).

## 4. Використання фреймворків і межа з бізнес-логікою

**Що добре**
- Правильне використання можливостей FastAPI: `APIRouter` з `prefix` і `tags`, `response_model`, `Depends`, `HTTPBearer`, `lifespan`, централізовані обробники винятків, `status_code` для 201/204.
- Правила предметної області (унікальність, ліміт вільного вибору) винесено в `model_validator`, тож вони спрацьовують автоматично й потрапляють у 422 єдиного формату.

**Що виправити**
- Бізнес-логіка живе в модулях маршрутів: фільтрація каталогу в `list_disciplines`, `_find_plan`, `_build_response`, дані `_CATALOG` і `_MOCK_PLANS`. Після підключення PostgreSQL цей код доведеться переписувати.
- `ApiError` містить HTTP-код (`status_code`), тож доменний шар знає про HTTP. Краще доменні винятки (`PlanNotFound`, `PlanNotEditable`), які в одному місці відображаються на HTTP.
- Константа `FREE_ELECTIVE_LIMIT` і правила навантаження мають бути в доменному шарі/конфігурації, а не у файлі схем.
- Структура пакетів плоска, тоді як `AGENTS.md` (ADR-001) описує три модулі: Core/Planning, SAZ Parser, Recommendation.
- Ендпоїнти оголошені `async def`, але без `await`. Із синхронною роботою з БД це блокуватиме event loop; потрібно або `def`, або асинхронний драйвер.
- Побічний ефект при старті: `save_openapi_spec` без `try/except` пише у файлову систему. У контейнері з режимом «лише читання» застосунок не запуститься.

## 5. Документація і статичний аналіз

**Що добре**
- Кожен файл має докстрінг модуля з нотаткою «Використання ШІ», як вимагає розділ 9 `AGENTS.md`.
- `Field(description=..., examples=...)`, `summary`, `description`, `responses` дають повну й зрозумілу OpenAPI-специфікацію; спека генерується автоматично, а не пишеться вручну.
- Коментар у `get_current_student_id` пояснює, чому існує `MCP_DEV_MODE`.

**Що виправити**
- Немає докстрінгів у `get_current_student_id`, `_build_response`, `health_check`, вкладених обробниках `register_error_handlers`. Описи в декораторах потрапляють у Swagger, але не допомагають читачеві коду.
- **Порожні `__init__.py`.** Для Python це не помилка: файл потрібен, щоб `src/api` і `src/api/routes` були звичайними пакетами, тоді відносні імпорти (`from ..common import ...`, `from .routes import ...`) працюють однаково в `uvicorn`, `pytest`, `mypy` та інструментах пакування (без нього вони стають namespace-пакетами, і поведінка інструментів різниться). Проте порожній файл — упущена можливість: потрібен докстрінг із призначенням пакета і, за правилом розділу 9 `AGENTS.md`, нотаткою «Використання ШІ» (кожен артефакт має її містити, навіть дрібний).
- Немає конфігурації статичного аналізу і звітів: файлів `pyproject.toml` (`ruff`, `mypy`), `.pre-commit-config.yaml`, кроку лінтера в GitHub Actions. У нотатках «Перевірка» вказано лише ручні запуски.

Рекомендовані команди (запустити й додати результат у цей звіт):

```bash
pip install ruff mypy bandit
ruff check src/ --select E,W,F,I,B,UP,S
ruff format --check src/
mypy src/ --strict
bandit -r src/
pytest --cov=src
```

## 3 сильні сторони

1. **Єдиний контракт помилок.** `ErrorResponse` + `ApiError` + чотири обробники дають однаковий формат для всіх 4xx/5xx, а `error_responses()` автоматично додає його в OpenAPI. Клієнт (фронтенд, MCP-сервер) має передбачувану поведінку, а внутрішні подробиці не витікають.
2. **Декларативна валідація й самодокументована схема.** Обмеження полів, enum-и, `model_validator` для бізнес-правил, пагінація з верхнім лімітом і приклади в схемах роблять API безпечним за замовчуванням і зрозумілим без окремої інструкції.
3. **Code-first документація й простежуваність.** OpenAPI генерується з коду при старті (YAML + JSON), тегами й `servers` налаштовано Swagger UI/ReDoc, а в кожному файлі є нотатка про використання ШІ та спосіб перевірки — це відповідає `AGENTS.md` і вимогам лабораторної.

## 3 пропозиції покращення

1. **Розділити шари й прибрати дублювання.** Створити `schemas/`, `services/` (логіка планів, правила 25/240/57–60), `repositories/` (поки in-memory) і `core/` (помилки, пагінація, автентифікація). Замінити `ApiError(status_code, ...)` на доменні винятки з однією таблицею відображення на HTTP. Винести спільні `PaginationParams` і `PlanIdPath` у залежності (`Annotated[..., Depends]`), а повідомлення про помилки — в одне місце.
2. **Перевіряти дані плану на сервері, а не довіряти клієнту.** У запиті залишити лише `discipline_id` і `trimester`; назву, кредити та `is_free_elective` брати з каталогу. Перевіряти ліміт 25 кредитів сумарно по всіх планах студента, а також 240 і 57–60 кредитів та конфлікти з нормативними дисциплінами. Для чужих планів повертати 404.
3. **Автоматизувати стиль і документацію.** Додати `pyproject.toml` з `ruff` (lint + format), `mypy` і `bandit`, `pre-commit` та крок у GitHub Actions; виправити зауваження з розділу 1; замінити `print` на `logging` із request ID; додати докстрінги функціям і непорожні докстрінги в усі `__init__.py` (призначення пакета + нотатка «Використання ШІ»).

## 1 потенційна вразливість / ризик

**Обхід автентифікації через змінну середовища `MCP_DEV_MODE=1`** (`src/api/common.py`, `get_current_student_id`).

- **Суть.** Якщо запит приходить без заголовка `Authorization` і `MCP_DEV_MODE == "1"`, функція повертає `MOCK_STUDENT_ID` замість 401. Перемикач глобальний для всього процесу, а не лише для MCP-сервера: будь-який HTTP-клієнт без токена отримує ті самі права.
- **Сценарій.** Змінну залишили в `.env`/Docker-образі, скопійованому в продакшн (або ввімкнули «на хвилинку» для налагодження) → усі ендпоінти стають доступними без входу, а після заміни заглушки на реальний JWT цей обхід залишиться в коді. Перевірка виконується на кожен запит і не лишає жодного сліду в журналі.
- **Класифікація.** CWE-306 (відсутня автентифікація критичної функції), CWE-489 (активний налагоджувальний код); OWASP API Security Top 10 2023: API2 Broken Authentication.
- **Серйозність.** Висока для продакшну (низька, поки це заглушка).
- **Усунення.**
  1. Не робити обхід у HTTP-шарі: MCP-сервер має викликати сервісний шар напряму або мати окремий внутрішній застосунок/порт.
  2. Якщо перемикач потрібен, вмикати його лише при `APP_ENV=development` і відмовляти в запуску (`raise RuntimeError`), коли `MCP_DEV_MODE=1` разом із `APP_ENV=production`.
  3. Писати попередження в журнал при старті й при кожному використанні обходу.
  4. Додати тест, який перевіряє, що без токена та з `MCP_DEV_MODE` не в режимі розробки повертається 401.
  5. Під час заміни заглушки перевіряти підпис JWT, `exp`, `aud` і домен пошти.
