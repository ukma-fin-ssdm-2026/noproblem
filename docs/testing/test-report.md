# Звіт про тестування: покриття та якість тестів

## 1. Як отримати звіт

```bash
pip install -r requirements-dev.txt
pytest --cov --cov-report=term-missing --cov-report=html
```

Налаштування покриття — у `pyproject.toml` (`[tool.coverage.*]`):

* `source = ["src"]` — вимірюється лише код застосунку;
* `branch = true` — враховуються не тільки рядки, а й гілки `if/else`;
* `fail_under = 90` — нижче цього порогу команда завершується з помилкою.

HTML-звіт лежить у **[`htmlcov/`](../../htmlcov/index.html)**: відкрийте
`htmlcov/index.html` у браузері, щоб побачити кожен файл із підсвіченими
непокритими рядками.

## 2. Підсумок

| | Тестових випадків | Покриття |
|---|---|---|
| До роботи над тестами | 146 | 95% (лише рядки) |
| Після ввімкнення покриття гілок | 146 | 93,6% (рядки + гілки) |
| **Зараз** | **237** | **96,7%** (рядки + гілки) |

pytest рахує кожен набір параметрів параметризованого тесту окремим
тестовим випадком. Більшість нових тестів параметризовані: 38 нових
тестових функцій дають близько 90 випадків, по одному на кожне граничне
значення.

Покриття гілок суворіше за покриття рядків: рядок з `if` вважається
покритим, лише якщо тести пройшли обидва варіанти умови. Тому після
його ввімкнення відсоток спершу знизився, але став чеснішим.

Фікстури та дублери для ізоляції від зовнішніх залежностей:

| Залежність | Дублер | Де |

| Час | `FakeClock`; `api_clock` підміняє `datetime.now` у маршрутах документів | `tests/fakes.py`, `tests/api/conftest.py` |
| Хешування паролів (Argon2) | `FakePasswordHasher` з лічильниками викликів | `tests/fakes.py` |

## 6. Пропозиції щодо якості тестів

### Уже виправлено

1. **Тест без перевірок.** `test_outdated_hash_is_upgraded_on_login` не
   містив жодного `assert` і пройшов би навіть без коду оновлення хешу.
   Додано лічильник `hash_calls` у `FakePasswordHasher` і перевірки.
   Тест перевірено мутацією: коли закоментувати перерахунок хешу в
   `service.py`, тест падає.
2. **Дублювання фікстур.** Фікстура `client` і хелпери були скопійовані в
   кожен файл `tests/api` з різницями між копіями. Винесено в
   `tests/api/conftest.py` і `tests/api/helpers.py`.
3. **Неперевірюваний час.** Маршрути документів беруть час напряму з
   `datetime.now()`, тож `created_at`/`updated_at` не можна було
   перевірити точно. Додано заглушку `api_clock`.
4. **Зайвий тест «під покриття».** Видалено тест, який лише закривав
   гілку у звіті й дублював інші перевірки.
5. **Стиль.** Виправлено зауваження black і flake8 у тестах, через які
   CI міг падати.

### Рекомендовано

1. **Перевести маршрути документів на порт `Clock`.** Тоді `api_clock`
   (підміна `datetime` через `monkeypatch`) стане непотрібним, а час
   передаватиметься в `create_app` так само, як в IAM. Це зміна коду
   застосунку, а не тестів, тож її варто зробити окремою задачею.
2. **Явні перевірки замість неявних.** Сім тестів (наприклад,
   `test_four_failures_do_not_lock`, `test_logout_is_idempotent`) не
   мають `assert` і перевіряють лише, що не виникло винятку. Явна
   перевірка результату (`assert result.user.email == ...`) робить
   намір тесту очевиднішим.
3. **Ізолювати `tests/test_metrics.py`.** Тести створюють застосунок без
   фікстур, тобто зі справжнім Argon2 і налаштуваннями з оточення.
   Варто використати спільну фікстуру `client`.
4. **Закрити корисні прогалини з розділу 5:** HTTP-тест для списку
   учасників, `find_user_by_email` з некоректним email, налаштування
   `SessionPolicy`.
5. **Додати покриття в CI.** Зараз поріг 90% перевіряється лише
   локально; крок `pytest --cov` у `.github/workflows/ci.yml` не дасть
   непомітно знизити покриття в PR.
6. **Організація `tests/iam/test_extra_coverage.py`.** Файл згруповано за
   вимогами завдання, а не за модулем; у довгостроковій перспективі його
   тести краще розкласти по `test_models.py` і `test_service.py`.
7. **Дрібниця в коді:** повідомлення журналу в
   `LoggingEmailSender.send` закінчується зайвим пробілом.
